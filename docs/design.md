# 媒体锚定事件映射设计

## 问题

重剪后，章节、强制字幕和普通字幕仍引用旧的绝对时间线时间，导致全部错位。
根因是把**派生性的时间线位置**当成了持久事实。本设计把持久事实改为
「事件在源媒体中的区间」（媒体锚点），时间线位置永远由 EDL 重新推导。

## 数据模型（纯整数时间）

- `Media`：源媒体，带稳定 ID 与时长。
- `Anchor{media_id, start_ticks, end_ticks}`：事件在某条源媒体中的半开区间，
  是唯一持久事实，不含任何时间线时间戳。
- `Event`：章节 / 强制字幕 / 普通字幕，携带可选锚点。无锚点的为遗留事件。
- `Segment`：EDL 条目，`源媒体区间 -> 新时间线起点`。同一源区间可出现多次
  （闪回、复用），这正是需要人工选择的情形。
- `Decision`：人工裁决，以稳定的片段键索引，只记录动作，不记录时间线时间。
- `AnchorDecision`：遗留事件的人工锚定结果。

所有时间用整数 `Ticks`，工程声明 `ticks_per_second`，全程无浮点。

## 映射语义

1. 对每个事件锚点，用所有覆盖它的 EDL 段边界把区间切成若干**片段**
   （`anchor/split.go`）。切分边界只来自源区间，确定性且与时间线位置无关。
2. 每个片段按覆盖段数量分类：
   - 1 个段：自动映射，`dst = seg.dst_start + (src_start - seg.src_start)`。
   - 多个段：`ambiguous`，输出全部候选，等待人工选择。
   - 0 个段：`removed`（素材被剪掉），等待人工删除或自定义放置。
3. 被切开的章节 / 字幕区间因此成为各自独立、可单独裁决的片段。
4. 遗留事件（无锚点）先进入人工锚定流程；多媒体工程不会猜测媒体归属。

## 人工选择如何持久且稳定

片段的稳定键为 `事件ID#媒体ID:源起点-源终点`（`anchor/keys.go`），
**不含时间线时间**。因此：

- 再次重剪移动了目标位置，键不变，已有人工选择继续生效。
- 选中的段不再覆盖该片段、或片段本身消失时，决策被标记为 `stale`
   并保留在磁盘上，绝不静默删除，由用户显式处理。
- 动作有三类：`segment`（选候选段）、`custom`（显式目标区间）、
  `drop`（接受素材删除）。

映射 `Project.Map` 是工程内容的纯函数：相同输入永远得到相同输出。

## 重开稳定性保证

- 保存用确定性 JSON（固定缩进，`encoding/json` 对 map 键排序）。
- 写入采用同目录临时文件 + 原子 rename，避免半写损坏。
- `Project.Checksum` 对规范化 JSON 取 SHA-256；保存→重载→映射结果与
  校验和必须逐字节一致（测试 `TestSaveLoadRoundTripIsStable` 守护）。

## 目录

- `anchor/`：可复用库（类型、校验、切分、映射、决策、持久化、时间解析）。
- `cmd/mediaanchor/`：仅依赖标准库的 CLI。
- `demo/`：`mediaanchor demo` 生成的示例工程。
